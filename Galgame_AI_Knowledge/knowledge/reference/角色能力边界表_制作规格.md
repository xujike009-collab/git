## 一、为什么要这张表（目的，不是装饰）

扮演者出现过一个具体问题：**模型倾向让每个角色都懂行**——因为模型自己什么都懂，就默认角色也懂。
后果是角色说出**本来没资格说**的话，例如：

- 朝日（半路入行）说出只有资深设计师才讲的话 → 不像她
- 露娜（设计天才但**型纸／立体裁断苦手**）突然精通报版 → 破坏她的质感

**这张表的作用是把"能力天花板"写成可执行的拦截**，让扮演者知道：
**这个角色能说什么、不能说什么、在哪里必须求人。**

> 用户原话：**「不要把人物设计成全知全能，根据原作中人物的认知来设计」**。
> 这不是人设润色，是**台词的资格边界**。

| 来源层 | 位置 | 本机可否验证 | 说明 |
|---|---|---|---|
| **台词层** | `characters/*.json` 的 `text`／`file`／`line` | ✅ **可精确验证** | 每条的 `file:line` 可直接对上 |
| **统计层** | `reports/character_stats.json`、`insights.json` | ✅ 可验证 | 频率／句尾／人称 |
| **旁白层** | `.s` 脚本里的叙述句 | ✅ **可精确验证** | 查 `cleaned\messages.jsonl` 的 `type=narration` 行（实测 **14040** 条）；必要时回 `raw\script_lines.jsonl`、`extracted\merged\**`（明文 `.s`） |
| **档案结论** | `knowledge/characters/*.md` 里的引用 | ✅ **可验证**（引用台词层查 `characters/*.json`；引用旁白层查 `cleaned\messages.jsonl` 的 `type=narration`） | 见下方更正说明 |

**规矩**：写入表里的每条锚点，**必须在你能实际打开的来源层里核对过**。
核不了的，写「未核实（来源层不可访问）」或干脆不收——**不要照抄别处看来的行号**。

**（2026-10-11 归档者更正，重要）** 本机数据层**齐全**：`raw/`、`cleaned/`、`extracted/` 只是被 `.gitignore` **排除出 Git**，**并未从本机删除**。

## 四、每个角色要产出什么（模板）

**每人一节，总长控制在 15 行以内。** 格式固定如下：

```markdown
### <角色名>

**优势**（有原文依据）
- <能力项>：<到什么程度>　→ `<file>:<line>`

**天花板 / 苦手**（有原文依据；查不到就写「未找到依据」）
- <能力项>：<到什么程度／为什么>　→ `<file>:<line>`

**分工依赖**（这件事他会／必须找谁）
- <事项> → 找 <谁>，因为 <原因>　→ `<file>:<line>`

**禁用（可执行拦截）**
- ✗ 不要让<角色>说出／做出：<具体行为>
```

**示例（⚠️ 仅格式示范：其中 `l07_01a.s:1552`／`l07_01a.s:1357` 两处行号经核**内容与结论不符**（分别为「業界関係者も大勢来る…」与「…ショーの衣装としての見た目もいいし…」），属**占位**，**禁止直接引用**；正式条目必须各自取证）**：

```markdown
### 桜小路ルナ

**优势**
- 设计：顶级，校内公认　→ `l07_01a.s:1552`
- 评审：冷彻且会给理由　→ `l07_01a.s:1357`

**天花板 / 苦手**
- 立体裁断：本人自称苦手　→ `c03_02a.s:2375`
- 型纸：苦手，会反复返工并向八千代请教　→ `u31_02a.s:3331`

**分工依赖**
- 缝制 → 交给朝日　→ `l07_01a.s:1797`

**禁用**
- ✗ 不要让她说"我来缝／我来打版"，也不要让她对型纸表现出自信
- ✗ 不要让她声称缝制作品出自自己之手
```

## 六、三条硬性规矩

**① 每条结论必须带锚点（`file:line`）。**
没有锚点的条目**不得写入**，只能写「未找到依据」。

**② 区分三类信息，不得混同：**
1. **客观能力**（原文直接展示／他人评价）
2. **自我认知**（角色自述"我没才能"——**不等于客观事实**）
3. **推测**（须显式标「推测」）

例：露娜说「だから苦手なんだ。立体裁断は」是**自述能力**（可验证）；
若某条"某角色才能不足"的结论**只**来自旁白或他人评价，须标明它是**哪一类**；
只用角色自述而**无客观依据**时，标为「自我认知」而非「客观能力」。

**③ 技能类台词可能夹带成人向内容——只取与工艺／能力相关的那句。**
本次核实中，露娜部分台词的**上下文**含成人向内容（原作本身是成人向作品，
但本 run 的角色设定为**未成年学生**）。**规格要求：**
- 只引用与**设计／型纸／裁断／缝制／审美判断**相关的原文
- **不得**引用、转述或概括任何性相关内容
- 若某条能力结论**只能**从成人向场景取得，**标记为「不宜引用」并跳过**，换别的证据

## 七、成品放哪

**路径**：`knowledge\reference\角色能力边界.md`（**由归档者创建并维护**）

**理由**（为何不写进 `knowledge\characters\*.md`）：
- 该表是**横切结构**（一线一人，含"对谁说话"与禁用项），与按角色纵向组织的档案不同构
- 避免多人同时改同一份人物档案

**文件头建议**：

```markdown
# 角色能力边界（归档者维护）

> 用途：给扮演者的「台词资格边界」——谁强在哪、谁弱在哪、什么话没资格说。
> 依据：`characters/*.json` 原台词库（每条附 `file:line`）；无依据者标「未找到依据」。
> 维护者：归档者（扮演者只读）。建立时间：2026-__-__。
```
