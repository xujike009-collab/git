# 工具使用速查卡

**用途**：本卡是「扮演者会话」与「归档者会话」执行导出、校验、定位、分段读取时的**命令与文件名依据**。
**版本**：1.0（2026-10-03）

> **本卡只管命令，不管权限。** 效力划分如下：
>
> | 内容类型 | 以谁为准 |
> | --- | --- |
> | **命令参数、文件路径、导出产物、校验步骤** | **本卡** |
> | **会话职责、文件写入权限、交接原则、禁止事项** | **`双会话协作规范.md`** |
>
> 这样划分是为了：将来修改本卡（例如调整分段大小、更换命令写法）
> **不会意外改变扮演者或归档者的权限与职责**。
> **两份文件出现实质性冲突时，暂停操作并向用户报告；不得自行选择有利于自己的规则。**

---

> 本卡只讲**怎么用工具**。它不判断剧情内容、不提取事件、不维护档案——
> 那些属于归档者的职责，见 `双会话协作规范.md` 第四、五节。

---

## 零、四条铁律

1. **`--split-every` 不可省略。** 不传它，工具**只产出完整记录 + 校验单两个文件**，归档者的分段读取、进度核对、`--lookup` 定位**全部无法执行**。
2. **导出命令写死，不要临时改动参数。** 两个会话看到的产出文件名必须一致。
3. **工具是只读的。** 它只读 DSH 会话文件，绝不修改、移动、删除任何原始记录。
4. **原始记录禁止清理。** `reports/sessions/` 下的导出文件、分段、索引、校验单属于项目原始资料，
   **归档完成后也不得删除、移动、覆盖或改写**，即使已经归档完毕。
   保留是为了日后复查、纠错和重新归档。详见规范 §6.1（**默认策略：长期保留、只读使用、禁止自动清理**）。

## 一、路径常量（复制用）

```powershell
$node = "C:\Users\salat\.workbuddy-ai\binaries\node\versions\22.22.2-2\node.exe"
$tool = "C:\Users\salat\Desktop\git\Galgame_AI_Knowledge\tools\export_session.mjs"
$out  = "C:\Users\salat\Desktop\git\Galgame_AI_Knowledge\reports\sessions"
```

> 用 WorkBuddy 自带的 Node。系统 PATH 上的 `node` 可能版本过低（zstd 需要 Node ≥ 22.15）。

## 二、导出流程（由用户执行）

> ### ⚠️ 由谁执行（2026-10-03 最终裁定）
>
> **导出由用户在一个普通 PowerShell 窗口执行**（不在任何 DSH 会话内），
> 且在**关闭扮演者会话之后**。
>
> **不要由扮演者会话自己导出**：导出动作本身（工具调用与工具结果）会写进被导出的会话，
> 归档者因此拿不到封闭快照，也无法核对「产物是否覆盖到最新一条剧情事件」。
> 关闭会话后在外部导出，产物才与原始记录有确定的时间关系。
>
> 扮演者的职责是：用户说存档时**停止工作并报告接续信息**，然后由用户执行下面的命令。

### 第 1 步：找到本会话 ID

```powershell
& $node $tool --list
```

输出按修改时间倒序排列，**最上面一行通常就是刚关闭的那个会话**。
记下它的 **会话 ID**（形如 `session-e6fd23f1-a717-...`；可用前 8 位作前缀）。

### 第 2 步：导出（命令固定）

```powershell
& $node $tool --session <会话ID前缀> --out $out --split-every 20
```

**`--split-every 20` 必须保留。**

### 第 3 步：确认产出齐全

工具输出末尾会打印「已写出」「分段」「校验单」三行。产出**由两部分构成**：

| 类别 | 文件 | 数量 |
| --- | --- | --- |
| **固定 4 个** | `<名>.md`（完整记录，末尾含完整性报告）<br>`<名>.index.md`（分段索引 + **读取进度表**）<br>`<名>.locate.md`（**消息定位索引**）<br>`SESSION-EXPORT-<会话ID>.sha256`（**旁置校验单**） | 恒为 **4** |
| **分段文件** | `<名>.turn-001-020.md`、`<名>.turn-021-040.md` … | `ceil(Turn 数 ÷ 20)` |

其中 `<名>` = `session-<完整会话ID>`。

> ### ⚠️ 产物总数不是固定的，不要硬编码
>
> **合计 = 4 + ceil(Turn 数 ÷ 20)**
>
> | Turn 数 | 分段数 | 合计 |
> | --- | --- | --- |
> | 40 | 2 | 6 |
> | 60 | 3 | 7 |
> | 97 | 5 | **9** |
> | 120 | 6 | 10 |
> | 200 | 10 | 14 |
>
> **核对时不要写「必须正好 9 个文件」**——那只是某一次导出的巧合数字。
> 正确做法：① 固定 4 个文件必须都在；② 分段文件从 `turn-001-020` 开始**编号连续**；
> ③ 末段的结束 Turn 与完整性报告里的 `Turn 数` 一致。
>
> 注意 `SESSION-EXPORT-<会话ID>.sha256` 的**文件名带会话 ID**，每个批次一份、互不覆盖。
> （早期版本用固定的 `SESSION-EXPORT.sha256`，后一次导出会覆盖前一次的校验单，
> 使旧批次无法再校验——已修正，现在多批可并存。）

### 第 4 步：确认完整性信息

工具输出里的这几项应为：

- `zstd 帧 : N（失败 0，坏行 0）` ← **失败与坏行都必须是 0**
- `统计数据 : Turn … / 用户 … / 注入 … / 助手 … / 工具调用 … / 工具结果 …`
- `⚠️ 待核对 : … 条` ← 若有，需人工看一下是什么

### 第 5 步：交给归档者

只需告诉归档者**会话 ID**，并说明产出在 `reports\sessions\`。
**不要把摘要当成原始记录的替代品。**
**不要删改任何导出文件。**
**不要执行 Git 提交。**

## 三、归档者：核验流程

### 第 1 步：确认文件齐全

```powershell
cd C:\Users\salat\Desktop\git\Galgame_AI_Knowledge\reports\sessions
Get-ChildItem | Where-Object { $_.Name -like '*<会话ID前缀>*' } | Select-Object Name,Length
```

应看到完整 `.md`、`.index.md`、`.locate.md`、若干 `.turn-*.md`，
以及该批次的校验单 `SESSION-EXPORT-<该会话ID>.sha256`。

### 第 2 步：核对 SHA-256（关键，不可跳过）

```powershell
cd C:\Users\salat\Desktop\git\Galgame_AI_Knowledge\reports\sessions
Get-Content .\SESSION-EXPORT-<会话ID>.sha256   # 先看校验单里声明的值
Get-FileHash *.md -Algorithm SHA256 | Format-Table Hash,Path
```

**逐一比对**。任何一项不一致 → **暂停归档，向用户报告**。

> `SESSION-EXPORT-<会话ID>.sha256` 里还记录了**原始会话文件**的 SHA-256 与 zstd 帧数。
> 注意：原始会话文件在对话进行中仍会被追加写入，所以那个哈希**只在导出那一刻成立**；
> 归档结束后原对话若继续产生新事件，重导出会得到不同的原始哈希，**属正常**。

### 第 3 步：看读取进度表

打开 `<名>.index.md`，里面是**分段 + 读取进度表**：

| 段 | 文件名 | Turn 范围 | 大小 | SHA-256 | 已读取 |
| --- | --- | --- | --- | --- | --- |
| 1 | `…turn-001-020.md` | 1–20 | … | … | ☐ |

**逐段读取，读完一段才勾选该段。**
**不要预先勾选未读的段，也不要把未读完的内容标记为已归档。**

### 第 4 步：按 ID 定位原文

记录里每条消息都带稳定 ID，形如 `` `[#1234]` ``：

```
### 👤 用户 `[#8]`　<sub>2026/10/2 20:39:11</sub>
#### 🔧 调用工具 `pwsh`
<details><summary>📤 工具结果 `pwsh` `[#24]`（1247 字符）</summary>
<details><summary>⚙️ [#9] 工作区指令注入（AGENTS.md 等）（1939 字符，非用户发言）</summary>
```

用 `--lookup` 反查它落在哪个文件第几行：

```powershell
& $node $tool --lookup 8 --index "$out\<名>.locate.md"
```

输出示例：

```
消息 ID   : `#8`
类型      : user/message
所属 Turn : 1
段文件    : `…turn-001-020.md`
段内行号  : 27
完整文件行: 22  （未分段时的行号）
```

也可以**人工查** `<名>.locate.md` 那张对照表（ID｜类型｜Turn｜段文件｜段内行｜完整文件行）。

**ID 是稳定的**，行号会随重新导出变化——**引用时优选用 ID。**

### 第 5 步：注意区分消息来源

`user/message` 事件里，**只有 `source.kind = "user"` 才是用户真正说的话**。
其余都已在导出时**折叠标注为「⚙️ …（非用户发言）」**，包括：

| `source.kind` | 含义 |
| --- | --- |
| `dsh-mnemon` | 记忆协议注入 |
| `tool-jobs` | 后台任务通知 |
| `model-selection` | 模型切换通知 |
| `agent-instructions` | 工作区指令注入（AGENTS.md 等） |
| `runtime-context` | 运行时上下文注入 |
| `skill-catalog` | 技能目录注入 |

**这些不是剧情内容，不要当成事件归档。**
同理，扮演者的调试文字、工具调用与工具结果，**都不是剧情事件。**

## 四、常用参数一览

| 参数 | 用途 |
| --- | --- |
| `--list` | 列出本机全部可导出会话 |
| `--session <ID或前缀>` | 指定要导出的会话 |
| `--out <目录>` | 输出目录（**固定用 `reports\sessions`**） |
| `--split-every N` | 分段导出（**固定用 20，不可省略**） |
| `--lookup <seq> --index <文件>` | 按消息 ID 反查位置 |
| `--assistants` | 列出本机代理预设 |
| `--home <路径>` | 覆盖 DSH_HOME |
| `--no-thinking` | 不导出模型思考过程（默认导出） |
| `--tool-detail N` | 工具摘要字符上限（默认 200） |
| `--no-redact` | 关闭脱敏（**不要用**，默认开启） |
| `--stdout` | 输出到屏幕而不写文件 |
| `-h` / `--help` | 显示帮助 |

完整说明见 `<KB>\PROJECT_STATE.md` 第 4 节。

## 五、常见错误与后果

| 错误做法 | 后果 |
| --- | --- |
| 导出时漏掉 `--split-every` | **没有分段、没有 `.index.md`、没有 `.locate.md`**；归档者无法分段读取、无法核对进度、无法用 `--lookup` 定位 |
| 用系统 PATH 上的 `node` | 可能版本过低，zstd 解压失败 |
| 把 `--out` 指到别处 | 归档者按约定去 `reports\sessions\` 找不到文件 |
| 归档前跳过 SHA-256 核对 | 无法证明读的是未被改动的版本 |
| 把 `⚙️` 折叠块当成剧情事件 | 会把系统注入内容误归档成剧情 |
| 只读摘要不读原文 | 违反规范 §4.2；归档结果不可追溯 |
| 未读完就标记完成 | 违反规范 §4.3；**绝对禁止** |
| 扮演者或归档者自行 `git commit` | 违反规范 §5.1；提交由用户执行 |
| 归档完成后删除原始导出文件 | 违反规范 §6.1；原始记录是证据，须长期保留 |

## 六、异常处理

| 情况 | 处理 |
| --- | --- |
| 工具报 `zstd 帧 …（失败 > 0）` 或 `坏行 > 0` | **暂停**，向用户报告，不要继续归档 |
| `SESSION-EXPORT-<会话ID>.sha256` 与实际文件不符 | **暂停归档**，向用户报告，要求重新导出 |
| `.index.md` / `.locate.md` 缺失 | 说明导出时漏了 `--split-every`，**要求重新导出** |
| 分段 Turn 范围没覆盖到最新 | 说明导出发生在更早时刻，**要求重新导出** |
| 找不到某条消息的 ID | 确认 ID 抄写正确；用 `<名>.locate.md` 人工检索 |
| 原始文件 SHA-256 与上次不同 | **正常**——原对话仍在追加写入，重导出必然不同 |

## 七、双会话交接速记

```
扮演者：--list 找 ID → 导出（--split-every 20）→ 确认固定 4 个 + 分段编号连续 + 失败/坏行=0
                        → 告诉归档者「会话 ID」
归档者：确认文件齐全 → 核对 SHA-256 → 按 .index.md 逐段读 → 用 ID/--lookup 定位原文
                        → 区分「[#seq] 真人与注入」→ 归档 → 输出报告
用户  ：检查归档报告 → 决定是否 Git 提交（两个会话都不提交）
```

**并发约定**：同一时间**只开一个会话**。需要归档时先关闭扮演者会话，归档结束后再开。
本项目**没有文件锁**，同时运行会造成静默覆盖。
